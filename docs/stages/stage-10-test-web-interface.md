## Решения

### Пресеты берутся с backend, а не зашиты в клиент

`GET /scenarios` возвращает готовые тела запросов. Тот же источник используют
автотесты (`backend/tests/test_scenarios.py`) и генератор
`docs/HAND_TESTING.md`. Зашить их копию в `scenarios.ts` означало бы завести
четвёртое место, где живёт одно и то же, — и оно разошлось бы с остальными
после первой же правки сценария.

Побочное следствие: шестой сценарий `high_frequency`, добавленный ревизией 2,
появился в интерфейсе кнопкой без единой строки кода на клиенте.

### Контекст клиента виден и редактируем

Форма показывает 14 полей ТЗ §3. Но если отправить **только** их, система
возьмёт профиль клиента из накопленной истории — и повторные нажатия Analyze
начнут давать разные ответы: устройство, засветившееся в прошлом запросе,
перестанет быть новым. Для инструмента ручной проверки это выглядело бы
как дефект (решение [D-10](../TZ.md#отклонения-и-решения)).

Поэтому контекст (`user_avg_amount`, `known_device_ids`, `previous_*`,
`txn_count_last_hour`) едет вместе с транзакцией. Прятать его было бы
нечестно, поэтому он лежит в разворачиваемом блоке «Контекст клиента» —
не мешает, но виден и доступен для правки. Очистить поля можно: там же
написано, что тогда произойдёт.

### Клиент ничего не вычисляет

`api.ts` содержит только HTTP. Ни порогов, ни правил, ни расчёта признаков —
это прямой запрет ТЗ §11. Любая такая копия разошлась бы с backend и начала
бы показывать не то, что система решила на самом деле.

Даже цвет вердикта берётся из `decision`, пришедшего в ответе, а не
вычисляется из `risk_score` по локальным порогам.

### Форма хранит строки, валидация — на backend

Поля формы — строки, пустое поле просто не отправляется. Проверять ввод на
клиенте значило бы завести вторую копию правил валидации. Вместо этого
ошибка 422 разбирается и показывается по полям:

```
HTTP 422 — Некорректные данные запроса
  amount: Input should be greater than 0
  ip_address: Value error, Некорректный IP-адрес: 'не-ip'
```

## Что показывает результат (ТЗ §8.3)

| Требование | Как сделано |
|---|---|
| Risk Score 0–100 | крупное число слева, рядом подпись |
| Decision | `APPROVE` / `CHALLENGE` / `BLOCK`, цвет полосы и текста |
| Risk Level | отдельной строкой |
| основные причины риска | список; политики отдельно от факторов модели |
| Feature Contributions / XAI | таблица со шкалой вклада, знаком и направлением |
| исходный JSON | в разворачиваемом блоке целиком |

Дополнительно показано `модель дала N → политики подняли до M`: без этого
непонятно, почему при слабых вкладах признаков решение CHALLENGE.

## Проверка вживую

Backend и frontend подняты одновременно, проверка в настоящем браузере.

**Все шесть пресетов через интерфейс:**

```
Normal transaction     0  APPROVE    —
New device            35  CHALLENGE  new_device
Unusual country       55  CHALLENGE  high_risk_country, unusual_country
Large amount          73  BLOCK      —
Multiple anomalies   100  BLOCK      impossible_travel, velocity_burst,
                                     high_risk_country, unusual_country, new_device
High frequency        60  CHALLENGE  velocity_burst
```

Числа совпадают с автотестами и `docs/HAND_TESTING.md` — источник один.

**Ручное изменение параметров даёт новый ответ** (требование ТЗ §15).
От сценария Normal изменены четыре поля: `amount` 100 → 5000,
`country` KZ → NG, `device_id` → `dev_attacker_9`,
`transaction_frequency` 3 → 30:

```
было : Risk Score 0    APPROVE    политик нет
стало: Risk Score 55   CHALLENGE  high_risk_country, unusual_country
       модель дала 9 → политики подняли до 55
```

**Обработка ошибок:** 422 разбирается по полям, недоступный backend даёт
понятное сообщение с ожидаемым адресом и командой запуска.

**CORS:** заголовок `access-control-allow-origin: http://localhost:5173`
отдаётся, преднастройки в backend менять не пришлось — адрес уже был
в `CORS_ORIGINS`.

## Найденная особенность окружения

Vite слушает **только IPv6** (`::1`):

```
LocalAddress LocalPort
------------ ---------
::1               5173
```

По адресу `http://localhost:5173` всё работает, а `http://127.0.0.1:5173`
даёт отказ в соединении. Это не дефект, но по такому адресу интерфейс
не откроется, поэтому в README указан именно `localhost`.

Сборка проходит в строгом режиме: `strict`, `noUnusedLocals`,
`noUnusedParameters`. Первая попытка сборки упала на небезопасном приведении
типа — пришлось разделить «тело сценария как словарь» и типизированный
запрос явным `as unknown as`, а не прятать проблему под `as never`.

Автотестов у интерфейса нет: он тонкий и целиком проверяется вживую, а
поведение backend уже покрыто 185 тестами. Заводить ради одной страницы
vitest и jsdom значило бы нарушить требование ТЗ о минимальности.

## Как запустить

Два терминала.

```bash
uvicorn app.main:app --reload --port 8000 --app-dir backend
```

```bash
cd frontend && npm install && npm run dev
```

Интерфейс: <http://localhost:5173>

Если backend поднят на другом адресе — скопируйте `frontend/.env.example`
в `frontend/.env` и укажите `VITE_API_URL`.
