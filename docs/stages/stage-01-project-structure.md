## Цель

Построить каркас репозитория и окружение так, чтобы все последующие этапы
писали код в заранее определённые места с уже готовыми контрактами:
конфигурацией, логированием, доменными исключениями и перечислениями.

## Что сделано

### 1. Окружение

| Компонент | Факт |
|---|---|
| Python | 3.14.2 (`C:\Python314\python.exe`) |
| Node.js | v24.13.0 |
| npm | 11.6.2 |
| Docker | **отсутствует** на машине разработки |
| venv | `.venv/` в корне проекта |

**Проблема и решение.** Python 3.14 — свежая версия, часть ML-библиотек ещё не имеет
бинарных колёс. Проверено фактически:

| Пакет | Установленная версия |
|---|---|
| fastapi | 0.141.1 |
| uvicorn | 0.53.0 |
| pydantic | 2.13.5 |
| pydantic-settings | 2.15.0 |
| numpy | 2.5.3 |
| pandas | **3.0.5** |
| scikit-learn | 1.9.1 |
| scipy | 1.18.1 |
| joblib | 1.6.0 |
| pytest / httpx | 9.1.1 / 0.28.1 |
| **lightgbm** | **4.7.0** (опциональный, установился) |
| **shap** | **0.52.0** (опциональный, установился) |

**Опциональные зависимости встали успешно**, поэтому проект получает
предпочтительный по ТЗ стек: LightGBM (§5) как основная модель и SHAP (§7)
как основной механизм объяснений. Fallback-ветки ([D-2](../TZ.md#отклонения-и-решения),
[D-3](../TZ.md#отклонения-и-решения)) остаются в коде как страховка для машин,
где эти колёса недоступны — на них же держится сборка Docker-образа.

Проверено не фактом установки, а работой (wheel ≠ работоспособность):

```
lightgbm 4.7.0 | shap 0.52.0
lgbm predict_proba ok: 0.8241
shap values shape: (3, 4)
```

> Замечание для этапа 07: `shap.TreeExplainer` на бинарном LightGBM в версии 0.52
> возвращает массив `(n_samples, n_features)`, а не список из двух массивов.
> XAI-модуль должен обрабатывать оба формата.

> **Внимание для следующих этапов:** установилась **pandas 3.0**, где Copy-on-Write
> включён по умолчанию, а строковые колонки получают dtype `str` вместо `object`.
> Код генерации датасета и препроцессинга пишется без chained assignment
> и без `applymap` (удалён в 3.0).

Отсюда решения [D-2](../TZ.md#отклонения-и-решения) (каскад выбора ML-библиотеки)
и [D-3](../TZ.md#отклонения-и-решения) (SHAP опционален, есть встроенный explainer).
Обязательный `requirements.txt` содержит только то, что гарантированно ставится.

### 2. Дерево каталогов

```
Shin/
├── backend/
│   ├── app/{api/routes, schemas, services, features, ml,
│   │        risk_engine, xai, business, store, core, config}
│   ├── data/{raw, processed}
│   ├── models/
│   ├── scripts/
│   ├── tests/
│   ├── requirements.txt
│   ├── requirements-optional.txt
│   └── pytest.ini
├── frontend/src/{components, pages, services, types, hooks, styles}
├── docs/{TZ.md, STAGES.md, TRACEABILITY.md, stages/}
├── docker/
├── .env.example
├── .gitignore
└── README.md
```

Отличие от схемы ТЗ §11 — одно и осознанное: `app/models/` переименован
в `app/schemas/`, потому что в проекте одновременно есть Pydantic-модели и ML-модели.
Разведены: **схемы** в `app/schemas/`, **ML-артефакты** в `backend/models/`.
Зафиксировано как [D-1](../TZ.md#отклонения-и-решения).

### 3. Конфигурация

`backend/app/config/settings.py` — класс `Settings` на `pydantic-settings`:

- **пороги Risk Score** (`risk_approve_max`, `risk_challenge_max`) с валидатором,
  который не даёт задать невозрастающие границы;
- **пути к артефактам** с методом `resolve()` — относительные пути из `.env`
  превращаются в абсолютные относительно корня проекта, поэтому запуск
  из любого каталога работает одинаково;
- **параметры датасета**, **XAI**, **бизнес-стоимости**, **CORS**;
- `get_settings()` кэширован через `lru_cache` — один экземпляр на процесс,
  используется как зависимость FastAPI.

`.env.example` покрывает все поля с комментариями на русском.

### 4. Ядро

| Файл | Содержимое |
|---|---|
| `core/logging.py` | идемпотентная настройка формата логов, `get_logger(__name__)` |
| `core/exceptions.py` | иерархия `ShinError` с `status_code` и `error_code`; API-слой переводит их в HTTP |
| `schemas/enums.py` | `Decision`, `RiskLevel`, `ImpactDirection`, `ScenarioKey` |

Доменные исключения намеренно **не** наследуют `HTTPException`: ML-слой и сервисы
ничего не знают про HTTP, перевод делает единственный обработчик в `main.py`.
